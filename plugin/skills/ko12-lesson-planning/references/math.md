# 수학 — 수업 설계 pedagogy (초등)

`ko12-lesson-planning`에서 과목이 **초등 수학**(초1–6)일 때 로드된다 (SKILL.md 과목 레지스트리).

핵심 교수 원리 한 줄: **학생이 먼저 풀고, 교사는 나중에 정리한다.** 풀이 방법을 시범 보인 뒤
따라 풀게 하는 수업이 아니라, 학생이 자기 방법으로 문제에 부딪힌 뒤 여러 풀이를 견주며 개념과
절차가 드러나게 한다. 아래 학년군별 협상 불가 원칙은 모두 이 한 줄에서 나온다.

## 확인(Clarify)

질문하기 전에, 대화 전체의 신호로부터 다음을 먼저 판단한다:

**1. 학년군.** 학년에서 다음 중 어느 밴드인지 결정한다:
- **초 1–2학년군** (`[2수NN-NN]`): 구체물 조작과 말로 설명하기. 문장제는 상황 유형(더하기·빼기의
  첨가·제거·합병·비교)과 모르는 자리(결과·변화·처음)가 핵심이다.
- **초 3–4학년군** (`[4수NN-NN]`): 구체물 → 그림 → 식으로 옮겨 가기. 수 모형, 배열, 분수 막대,
  수직선이 주 표현이다.
- **초 5–6학년군** (`[6수NN-NN]`): 그림·표·식을 오가며 관계를 일반화하기. 비와 비율, 약수와 배수,
  분수·소수의 연산에서 풀이를 글로 설명하기가 시작된다.
- ⚠ **중·고 수학은 이 포크에서 아직 준비 중이다**(레지스트리 planned). 교사에게 알리고 초등 수학으로
  도울 일이 있는지 묻는다. 초등 밴드 구조를 중·고 수업에 늘려 쓰지 않는다.

**2. 영역.** 2022 개정 수학과는 **수와 연산 / 변화와 관계 / 도형과 측정 / 자료와 가능성** 4영역이다.
영역은 주로 표현 선택을 바꾼다(아래 *표현 고르기*). 코드의 영역 자리(`[4수01-…]`의 `01`)만으로 영역을
단정하지 말고 학습맵의 `domainKorean`으로 확인한다.

**3. 교과서 중립.** 성취기준은 공통, 교과서는 검정제다. 교과서의 문제·삽화·활동을 재현하지 않는다.
교사가 교과서 차시를 말하면 "몇 단원쯤인지" 위치 감각으로만 쓴다. 문제의 수와 맥락은 새로 만든다.

**4. 성취기준·소재 맥락.** 교사가 코드(예: `[4수01-11]`)나 주제를 명시했는지, 단원 안의 위치를 말했는지
확인한다. 없으면 학습맵에서 끌어오고, 모델이 고른 것은 "제안됨" 표시를 단다.

핵심 정보가 없으면 묻는다. 우선순위: (1) 학년, (2) 주제 또는 성취기준, (3) 단원 안의 위치 —
**이 차시가 개념을 처음 만나는 차시인지, 이미 배운 것을 익히는 차시인지** (수학은 둘의 설계가 완전히
다르다), (4) 차시 분량. 나머지는 추론한다. 침묵 기본값: **초 40분** 단일 차시, 과정중심평가 연계,
보편적 학습 설계, 개념 도입 차시.

## 수업 설계

**모든 수업 공통**

- **시각 표현 최소 1개**를 `shared`에 등록하고 수업안에 교사용 근거(왜 이 표현인지)와 함께 둔다 —
  `number_line`, 학생이 채우는 `fill_table`, 문제들이 함께 쓰는 `data_table`. 학생이 직접 표시하거나
  채우는 것은 학습지에도 싣고, **풀이 구조나 답을 보여 주는 참고표는 교사용에만** 둔다 — 인쇄하면
  학생이 할 생각을 대신해 버린다.
- 렌더러는 그림을 그리지 못한다. 분수 막대·배열·도형처럼 그림이 필요한 표현은 (a) `number_line`이나
  표로 바꿀 수 있으면 바꾸고, (b) 아니면 학생이 **직접 그리게** 하고(`answer_box` `ruled: false`),
  (c) 교사가 칠판이나 구체물로 보여 주는 것은 준비물과 해당 단계에 이름을 적는다.
- 전체 및 단계별 시간 배분이 현실적이어야 한다. 구체물을 쓰는 수업은 배부·회수(각 2–3분)를 단계
  안에 넣는다.

### 수업 흐름 — 문제 중심 5단계

모든 학년군이 같은 뼈대를 쓴다: **문제 만나기 → 스스로 해결하기 → 풀이 나누기 → 정리하기 → 정리 문항.**
기본 배분(40분): 문제 만나기 5 / 스스로 해결하기 12 / 풀이 나누기 10 / 정리하기 8 / 정리 문항 5.

- **문제 만나기 — 4–6분**: 앵커 문제 하나를 학생의 생활 맥락으로 제시한다. 풀이 방법을 알려 주지
  않는다. 무엇을 묻는지, 무엇을 알고 있는지만 학생 말로 확인한다.
- **스스로 해결하기 — 10–14분**: 혼자 → 짝. 구체물·그림·식 중 무엇을 써도 된다고 먼저 말한다. 교사는
  순회하며 풀이를 **분류**한다(누구의 풀이를 어떤 순서로 발표시킬지 정하는 일이다). 관찰 포인트 3개
  이상 — 각각 학생의 구체적 반응, 그것이 왜 중요한지, 교사가 할 일. 앵커 문제의 정답 식이나 풀이가
  둘 이상이면, 관찰 포인트 하나에 그 사실을 적어 교사가 모두 받아들이게 한다.
- **풀이 나누기 — 10분 이상 (줄이지 않는다)**: 순회 중 고른 풀이 2–3개를 **구체물 → 그림 → 식** 순서로
  발표시키고, 풀이끼리 무엇이 같은지 묻는다. 학생끼리 주고받는 말하기 방식 하나 이상을 이름으로
  쓴다(짝과 비교하기, 생각-짝-나누기, 친구 풀이 다시 말하기, 동의·반대 손 신호). 발문은 이 문제의 수와
  구조에 기반해 구체적으로 쓴다. 짧은 차시로 요청받아도 이 단계가 아니라 다른 단계를 줄인다.
- **정리하기 — 6–10분**: 학생 말로 나온 개념·절차를 교사가 수학 용어로 이름 붙이고(용어는 여기서 처음
  준다), 연습 문제로 확인한다. 연습 문제는 아래 *문제 구조 사례*를 모두 덮는다.
- **정리 문항 — 3–5분**: 아래 *정리 문항 지침*.

### 학년군 분기 — 초안 작성 전에 적용

#### 초 1–2학년군: 구체물과 말, 상황 유형과 모르는 자리

- 스스로 해결하기에 **구체물**(바둑돌, 연결 큐브, 수 모형)이나 그림이 반드시 있다. 식은 구체물 뒤에 온다.
- 덧셈·뺄셈 문장제 성취기준이면 문제 세트가 **상황 유형 넷**(첨가, 제거, 합병·분리, 비교)을 모두 담고,
  **처음을 모르는 문제 또는 변화를 모르는 문제**가 적어도 하나 있다. 정리 문항은 그 둘 중 하나다.
- 학생이 풀기 전에 풀이 방법을 시범 보이지 않는다.
- 학생이 쓰는 시각 모델(수 막대, 가르기·모으기 그림, 그림 그리기)은 학습지나 게시물에 **실제로 있다** —
  "필요하면 그려 보세요"라는 권유로 대신하지 않는다.
- 답은 수·그림·짧은 말로 받는다. 긴 설명 글쓰기를 요구하지 않는다.

**초 1–2 협상 불가 원칙:**
- 구체물 없이 식부터 시작하지 않는다.
- '모두', '남은' 같은 **낱말로 연산을 고르게 하는 전략**을 가르치지 않는다 — 상황의 구조를 보게 한다.

#### 초 3–4학년군: 구체물 → 그림 → 식, 표현 사이 옮기기

- 스스로 해결하기에서 학생이 고른 표현을, 풀이 나누기에서 **다른 표현으로 옮겨 보게** 한다(분수 막대
  그림 ↔ 수직선 ↔ 분수 표기, 수 모형 ↔ 세로셈).
- 풀이 나누기에 배열·넓이 모델, 수직선 중 하나가 반드시 등장한다.
- 연습 문제는 쉬운 사례에서 어려운 사례로 가되, 어려운 사례를 선택 문제로 빼지 않는다.

**초 3–4 협상 불가 원칙:**
- 계산 절차를 먼저 가르치고 원리를 나중에 붙이지 않는다 — 원리가 드러나는 표현이 먼저다.
- 표현은 장식이 아니다. 그림이 식의 각 수와 어떻게 대응하는지 학생이 말할 수 있어야 한다.

#### 초 5–6학년군: 관계와 일반화, 풀이 설명 쓰기

- 표·수직선·비율표·식을 오가며 **여러 사례에서 규칙을 찾아 일반화**하게 한다.
- 풀이 나누기에서 풀이의 **타당성**을 따진다: "이 방법은 언제나 되나요? 안 되는 수가 있나요?"
- 정리 문항이나 연습 문제 하나는 **풀이를 글로 설명**하게 한다(`answer_box` `ruled: true`).
- 성취기준의 수 범위가 분수·소수이면 적어도 한 문제는 분수나 소수를 쓴다 — 자연수만으로 덮지 않는다.

**초 5–6 협상 불가 원칙:**
- 공식·알고리즘을 발견 없이 주지 않는다. 공식은 학생이 찾은 규칙의 이름으로 정리하기에서 준다.
- 답만 맞은 풀이를 '이해함'으로 분류하지 않는다 — 까닭이 있어야 한다.

### 표현 고르기 — 개념 유형별 주 표현

| 개념 유형 | 주 표현 | 렌더러 처리 |
|---|---|---|
| 부분-전체, 덧셈·뺄셈 관계 | 수 막대(테이프 그림), 가르기·모으기 그림 | 학생이 그림 (`answer_box` `ruled: false`) |
| 곱셈·나눗셈 구조, 넓이 | 배열, 넓이 모델 | 학생이 그림 또는 모눈 `fill_table` |
| 분수·소수의 크기와 위치 | 수직선, 분수 막대 | `number_line` (분수 막대는 학생이 그림) |
| 비와 비율, 규칙과 대응 | 표, 비율표 | `fill_table` / `data_table` |
| 도형의 성질 | 이름 붙인 그림 | 교사가 칠판·구체물로 제시, 학생이 그림 |
| 자료와 가능성 | 표, 그래프 | `data_table`, 학생이 그래프 그림 |

### 문제 세트 — 구조 사례를 빠짐없이

연습 문제(`shared.p1`..`pN`)를 쓰기 전에, 이 성취기준의 **구조 사례를 열거**한다 — 모든 학생이 넘어야 할
기본 사례부터 학생이 가장 자주 틀리는 가장 어려운 사례까지. 예:

- 받아내림이 **없는** 뺄셈 / 받아내림이 **있는** 뺄셈 / **십의 자리가 0인** 수에서 빼기
- 분모가 같은 분수 비교 / **단위분수 비교(분모가 클수록 작다)**
- 나누어떨어지는 나눗셈 / **나머지가 있는 나눗셈과 그 나머지의 해석**
- 곱이 두 수보다 큰 곱셈 / **(진분수)×(자연수)처럼 곱이 작아지는 곱셈**
- 문장제에서 결과를 모르는 문제 / **처음이나 변화를 모르는 문제**

그다음 **열거한 모든 사례가 번호 붙은 필수 문제(또는 정리 문항)**로 들어가게 쓰고, 각 문제의 `teacher`
면에 그 문제가 맡은 사례의 이름을 적는다.

- 산문(학습 목표, 예상 반응, 교사 발문)에만 나오는 사례는 덮은 것이 아니다. 문제로 학생 앞에 놓는다.
- 가장 어려운 사례를 강조한다고 기본 사례를 빼지 않는다.
- 필수 사례를 '도전 문제'나 '더 해 보기'로 빼지 않는다 — 그러면 대부분의 학생이 만나지 못한다.
- 어느 문제가 어느 사례를 맡는지 교사용에 **한 번에 볼 수 있게** 적는다(수업안 정리하기 단계의 표).

### 섹션 구조 — 모든 학년군 공통

1. **한눈에 보기** — 성취기준 원문을 `special` 콜아웃에 verbatim(이 한 번만; 다른 곳은 코드 + 10어절 이내
   요지); 단계와 분을 명시한 한 줄 흐름; 앵커 문제(모델이 골랐으면 [제안]); 준비물 — 구체물은 이름과
   수량을 평이하게("수 모형 십 모형 10개, 일 모형 20개, 모둠당"); 이 차시가 기르는 **수학 교과 역량**
   1–2개(문제해결 / 추론 / 의사소통 / 연결 / 정보처리 중)를 이름으로.
2. **범주별 학습 목표** — **지식·이해** ("학생은 ___임을 이해한다"), **과정·기능** ("학생은 [구체물로
   나타내다·그림으로 나타내다·비교하다·계산하다·설명하다·추론하다 중 이 차시의 동사]하여 ___할 수
   있다"), **가치·태도** ("학생은 ___하는 태도를 보인다" — 관찰 가능한 행동으로: 틀린 풀이도 끝까지
   설명한다, 다른 풀이를 자기 말로 다시 말해 본다). 세 범주를 합치지 않는다.
3. **선수 학습과 단원 맥락** — 선수 성취기준 코드 + 학생이 이미 할 수 있는 것과 오늘이 그 위에 무엇을
   쌓는지 한 문장. 단원 안 위치를 교사가 말했으면 배치하고, 아니면 개념으로 연결한다.
4. **어휘** — 이 차시가 **정리하기에서** 이름 붙이는 용어 3–5개, 학생 친화적 정의와 함께.
5. **예상되는 학생 반응** — 2–3개. 각각 **틀린 식이나 틀린 답의 형태를 구체적으로** 쓴다(예: "1/3과 1/5
   중 1/5이 더 크다고 쓴다", "403−158을 355로 쓴다" — 계산해 보면 245). 형식: *학생의 반응* / *그렇게
   되는 이유* / *교사의 대응*. "개념이 부족하다" 같은 일반 서술은 실패다.
6. **수업 전개** — 위 5단계; 관찰 포인트, 말하기 방식, 구체적 발문, 문제-사례 대응표.
7. **설계 노트** — 정리 문항 뒤 마지막 섹션: 변형할 때 지킬 요소 2–3개와 범주별 이유. 이 수업의
   **중심 표현**(학생이 다루는 시각 모델)과 그 이유 한 문장을 포함한다.

→ **섹션 구조 완료. (교사가 선택했으면) 초안으로, 아니면 Step 5로.**

## 정리 문항(exit ticket) 지침

정리 문항은 수업 전개의 마지막 단계다 (`from_shared:exit_ticket`).

- 정리 문항은 열거한 사례 중 **가장 어려운 사례**다(초1–2 문장제: 처음이나 변화를 모르는 문제). 중간
  난도로 대신하지 않는다. **오개념 시험**으로 고른다: 이 차시의 대표 오개념을 가진 학생이 정리 문항을
  **틀려야** 한다. 그 학생도 맞힐 수 있는 문항이면 판별력이 없는 것이니 바꾼다. `shared.exit_ticket.teacher`에
  맡은 사례를 적는다.
- 연습 문제를 그대로 되풀이하지 않는다 — 새 수, 새 맥락.
- **모든 답을 직접 풀어 확인한다.** 정답, 예시 풀이, 수직선의 눈금과 표시, 표의 수가 실제로 맞아야 한다.
  계산 단계 수도 성취기준과 맞춘다(한 단계 성취기준이면 한 단계 문항).
- 분류 3칸 — *이해함 / 거의 / 재지도 필요* — 각 칸에 **그 칸의 답이 무엇을 담고 있는지** 기준을 쓴다
  ("이해함: 1/4이 크다고 쓰고, 같은 전체를 더 적게 나눴다는 까닭을 댄다"). 딱지만 쓰지 않는다.
  과정중심평가 기록과 연계할 수 있게 교사용 문서에 1줄로 명시한다.

## lesson.json 작성 — 수학 매핑

- `shared.subject`: `"수학"` — 렌더러가 이 값으로 수학을 알아보고 초1–5 답란을 **줄 없는 풀이 공간**으로
  잡는다. 문장으로 답하는 칸만 `answer_box` `ruled: true`로 둔다.
- `shared.grade`: **영문 학년을 먼저 쓴다** — `"Grade 4 · 초등학교 4학년"`. 렌더러가 첫 숫자로 답란 크기를
  정한다. 교사가 보는 학년 표기는 각 문서의 `meta`에 한국어로.
- `shared.standard_code` / `shared.standard_text`: 코드와 공식 원문. ⚠ 초등 수학 `officialText`에는 문장
  끝 **뒤에** 다음 소주제 이름이 붙어 오는 절취 결함이 있다(예: `[4수01-11]` "…설명할 수 있다. 소수").
  **문장을 끝내는 "다." 뒤의 꼬리만** 잘라 내고, 문장 안은 한 글자도 고치지 않는다. 잘랐으면 수업안
  설계 노트 끝에 한 줄로 밝힌다: *"성취기준 원문 끝에 붙어 온 다음 소주제 이름(…)을 뺐습니다 — 학습맵
  절취 결함. 공식 고시문과 대조해 확인하세요."*
- `shared.anchor_task`: `{teacher: <제시 방법 + 촉진 메모, 풀이를 알려 주지 않는 방법>, student: <학생이 읽는
  문제, 2인칭>}`.
- `shared.p1`..`pN`: 연습 문제 하나에 키 하나 — `{student: <문제>, teacher: <이 문제가 맡은 구조 사례 + 볼 것>}`,
  필요하면 `stimulus: [number_line 등]`. 여러 문제가 함께 쓰는 자료는 자기 키로.
- 시각 표현은 자기 키로 등록한다(예: `shared.fraction_line` — `number_line`, `shared.compare_table` —
  `fill_table`). 학생이 표시하거나 채우는 것만 학습지에 당겨 쓴다.
  학생이 분수·소수의 **위치를 찾는** 수직선은 `labels: "ends"`로 양 끝 값만 적는다 — 눈금 값이 모두
  찍히면 답이 인쇄된다. 눈금 수(`ticks`)는 분모와 같게 둔다.
- `shared.exit_ticket`: `{student: <새 문항>, teacher: <맡은 구조 사례 + 수합 메모>}` + 수업안에 분류 `cards`.
- `shared.vocabulary`, `shared.misconceptions`(table), `shared.look_fors`(list) — 관찰 포인트 앞에 범주를
  접두한다(`[과정·기능]` 등).
- `shared.smps`는 **쓰지 않는다**(미국 CCSS 수학적 실천). 교과 역량은 수업안 *한눈에 보기*에 `labeled`로 쓴다.

**학생 문서 배치**(`id: "student_materials"`) — 이 뼈대에서 출발해 수업에 맞춘다:

```
sections:
  "<문제 만나기, 학생 말로>"   group[ from_shared:anchor_task, answer_box(ruled: false) ]
  "<연습 제목>"               from_shared:<시각 표현 키>   ← 학생이 표시·기록하는 것일 때만
                             문제 k마다:
                               group[ {type: from_shared, key: pk, label: "k"},
                                      answer_box (풀이 공간 — 문장 답이면 ruled: true) ]
                             page_break
  "<정리, 학생 말로>"          group[ from_shared:exit_ticket, answer_box ]
```

**관찰 템플릿 배치**(`id: "observation_template"`): 사용법 / 관찰 포인트 + `fill_table`(학생 · 본 풀이 ·
다음에 할 일, 빈 행 8) / 예상되는 학생 반응 / 정리 문항 분류.
